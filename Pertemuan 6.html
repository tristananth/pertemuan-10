Step 1: Memastikan Composer

Pastikan Composer sudah terinstall dengan benar di sistem Anda.

Verifikasi Instalasi:
composer --version
Tips:
  • Jika Composer belum terinstall, download dari getcomposer.org
  • Pastikan PHP sudah ditambahkan ke PATH environment variable
  • Minimum PHP version: 8.0 atau yang direkomendasikan Laravel
Peringatan:

Pastikan tidak ada conflict dengan Composer version lama. Gunakan selalu versi terbaru untuk kompatibilitas dengan Laravel.

Step 2: Diskusi Konsep MVC dalam Laravel

MVC (Model-View-Controller) adalah architectural pattern yang memisahkan aplikasi menjadi tiga komponen utama.

Arsitektur MVC dalam Laravel

Model

Mewakili data dan business logic

app/Models/
Controller

Menangani request dan response

app/Http/Controllers/
View

Menampilkan data ke user

resources/views/
Alur Kerja MVC di Laravel:
  1. Request dari user masuk melalui Route
  2. Route mengarahkan request ke Controller yang sesuai
  3. Controller memproses request dan berinteraksi dengan Model
  4. Model berinteraksi dengan database dan mengembalikan data
  5. Controller menerima data dari Model dan mengirim ke View
  6. View menampilkan data dalam format HTML ke user
Contoh Alur MVC:
// routes/web.php
Route::get('/users', [UserController::class, 'index']);

// app/Http/Controllers/UserController.php
public function index()
{
    $users = User::all(); // Model
    return view('users.index', compact('users')); // View
}

// resources/views/users/index.blade.php
@foreach($users as $user)
    {{ $user->name }}
@endforeach

Library Management dengan Composer

Mengelola library/packages dalam project Laravel menggunakan Composer.

1. Cara Upgrade Library via CMD

Dua metode upgrade:

a. Upgrade satu library tertentu:
composer update vendor/nama-library

Contoh:

composer update barryvdh/laravel-dompdf
b. Upgrade semua library sekaligus:
composer update
Catatan:

Pastikan sistem kompatibel dengan Laravel versi kamu, karena upgrade besar bisa menyebabkan konflik versi.

2. Cara Downgrade Library via CMD

Untuk downgrade (menurunkan versi library):

1. Edit file composer.json

Ubah versi library secara manual. Misalnya:

"require": {
    "barryvdh/laravel-dompdf": "^1.0"
}

Ganti menjadi:

"require": {
    "barryvdh/laravel-dompdf": "0.9.*"
}
2. Jalankan perintah:
composer update barryvdh/laravel-dompdf
Keterangan:

Tanda ^ artinya "boleh versi yang lebih baru tapi tidak merusak kompatibilitas", sedangkan * artinya "boleh versi mana saja dalam rentang tersebut".

3. Cara Menghapus Library

Jika library sudah tidak diperlukan:

composer remove vendor/nama-library

Contoh:

composer remove barryvdh/laravel-dompdf
Composer akan otomatis:
  • Menghapus library dari vendor/
  • Menghapus entri di composer.json

Step 8: Menambahkan Route Resource

Daftarkan route resource untuk menghubungkan URL dengan controller.

Edit routes/web.php:
<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\MahasiswaController;

// Tambahkan route resource
Route::resource('mahasiswa', MahasiswaController::class);
Penjelasan:

Route::resource() secara otomatis membuat 7 route lengkap CRUD yang diarahkan ke method sesuai nama di controller.

Route yang Dihasilkan:
URL HTTP Method Aksi Method Controller
/mahasiswa GET Lihat semua data index()
/mahasiswa/create GET Tampilkan form tambah create()
/mahasiswa POST Simpan data baru store()
/mahasiswa/{id} GET Tampilkan detail show()
/mahasiswa/{id}/edit GET Tampilkan form edit edit()
/mahasiswa/{id} PUT/PATCH Update data update()
/mahasiswa/{id} DELETE Hapus data destroy()
Tips Routing:
  • Gunakan php artisan route:list untuk melihat semua route yang tersedia
  • Route name otomatis dibuat: mahasiswa.index, mahasiswa.create, dll
  • Gunakan route name di view dengan helper route()

Step 10: Mengisi Logika Dasar di Controller

Implementasikan logika dasar pada controller untuk menangani request.

Edit app/Http/Controllers/MahasiswaController.php:
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;

class MahasiswaController extends Controller
{
    /**
     * Display a listing of the resource.
     */
    public function index()
    {
        $data = ['Andi', 'Budi', 'Citra'];
        return view('mahasiswa.index', compact('data'));
    }

    /**
     * Show the form for creating a new resource.
     */
    public function create()
    {
        return view('mahasiswa.create');
    }

    /**
     * Store a newly created resource in storage.
     */
    public function store(Request $request)
    {
        $nama = $request->input('nama');
        return "Mahasiswa bernama <b>$nama</b> berhasil ditambahkan!";
    }

    /**
     * Display the specified resource.
     */
    public function show($id)
    {
        return "Menampilkan detail mahasiswa dengan ID: $id";
    }

    /**
     * Show the form for editing the specified resource.
     */
    public function edit($id)
    {
        return "Form edit mahasiswa dengan ID: $id";
    }

    /**
     * Update the specified resource in storage.
     */
    public function update(Request $request, $id)
    {
        return "Update mahasiswa dengan ID: $id";
    }

    /**
     * Remove the specified resource from storage.
     */
    public function destroy($id)
    {
        return "Hapus mahasiswa dengan ID: $id";
    }
    public function test()
    {
        // coba akses {URL}/mahasiswa/test
        // harusnya akan kepanggil function show karena /test itu dianggap {id}
        // harus tambahkan route terlebih dahulu
        return "Test function";
    }
}
Penjelasan Method:
  • index() - Menampilkan semua data mahasiswa
  • create() - Menampilkan form tambah data
  • store() - Menyimpan data baru dari form
  • show() - Menampilkan detail data
  • edit() - Menampilkan form edit data
  • update() - Memperbarui data yang diedit
  • destroy() - Menghapus data
Konsep Penting:
  • compact('data') - Mengirim variable $data ke view
  • $request->input('nama') - Mengambil data dari form input
  • view() - Memuat template Blade
  • Semua method menerima parameter sesuai kebutuhan

Tambahan — Database Migration Laravel

Apa itu Migration?

Migration adalah fitur Laravel yang digunakan untuk mengelola struktur database menggunakan kode PHP. Dengan migration, kita dapat membuat tabel, menambah kolom, mengubah struktur tabel, maupun memasukkan data awal tanpa harus melakukan export atau import file SQL.

Migration sangat penting dalam pengembangan tim karena struktur database dapat dibagikan kepada developer lain hanya dengan menjalankan perintah migration.

Kapan Migration Digunakan?
  • Ketika membuat tabel baru
  • Ketika menambahkan kolom baru pada tabel
  • Ketika ingin memasukkan data awal (statis)
  • Ketika ingin mengubah struktur database tanpa manual SQL
Membuat Migration

Untuk membuat migration baru gunakan perintah artisan berikut:

php artisan make:migration create_mahasiswa_table

Perintah tersebut akan membuat file migration baru di folder: 

database/migrations/
Contoh Migration Membuat Tabel Mahasiswa
use Illuminate\Database\Migrations\Migration;
                use Illuminate\Database\Schema\Blueprint;
                use Illuminate\Support\Facades\Schema;

                return new class extends Migration
                {
                    public function up()
                    {
                        Schema::create('mahasiswa', function (Blueprint $table) {
                            $table->id();
                            $table->string('nim');
                            $table->string('nama');
                            $table->string('jurusan');
                            $table->timestamps();
                        });
                    }

                    public function down()
                    {
                        Schema::dropIfExists('mahasiswa');
                    }
                };
Penjelasan:
  • up() → dijalankan ketika migration dijalankan
  • down() → dijalankan ketika migration dibatalkan (rollback)
  • Schema::create() → membuat tabel baru
  • $table->string() → membuat kolom tipe string
  • $table->timestamps() → membuat kolom created_at dan updated_at
Menjalankan Migration

Untuk menjalankan migration dan membuat tabel di database:

php artisan migrate

Perintah ini akan menjalankan semua file migration yang ada di folder:

database/migrations
Membatalkan Migration (Rollback)

Jika ingin membatalkan migration terakhir:

php artisan migrate:rollback

Perintah ini akan menjalankan fungsi down().

Menambahkan Kolom Baru

Jika ingin menambahkan kolom baru pada tabel yang sudah ada:

php artisan make:migration add_alamat_to_mahasiswa_table

Contoh isi migration:

Schema::table('mahasiswa', function (Blueprint $table) {
                    $table->string('alamat');
                });
Insert Data Awal (Data Statis)

Kadang kita perlu memasukkan data awal seperti data kategori, data role user, atau data master. Data ini bisa dimasukkan menggunakan migration. 

DB::table('mahasiswa')->insert([
                    [
                        'nim' => '22001',
                        'nama' => 'Andi',
                        'jurusan' => 'Informatika'
                    ],
                    [
                        'nim' => '22002',
                        'nama' => 'Budi',
                        'jurusan' => 'Sistem Informasi'
                    ]
                ]);
Kesimpulan:
  • Migration digunakan untuk mengelola struktur database menggunakan kode
  • Tidak perlu lagi export/import file SQL
  • Struktur database dapat dibagikan kepada developer lain dengan mudah
  • Cukup menjalankan perintah php artisan migrate

Tambahan — Tips & Best Practice CRUD Laravel

Saat membuat fitur CRUD (Create, Read, Update, Delete), penting untuk memperhatikan aspek keamanan, integritas data, dan performa sistem. Berikut beberapa praktik yang umum digunakan dalam pengembangan aplikasi Laravel agar sistem lebih aman, stabil, dan profesional.

Menggunakan Soft Delete

Soft Delete memungkinkan data yang dihapus tidak benar-benar dihapus dari database, tetapi hanya diberi tanda bahwa data tersebut sudah dihapus. Laravel menyimpan informasi ini pada kolom deleted_at. 

use Illuminate\Database\Eloquent\SoftDeletes;

                class Mahasiswa extends Model
                {
                    use SoftDeletes;
                }

Tambahkan kolom soft delete pada migration:

$table->softDeletes();

Dalam implementasi nyata, Controller biasanya mengatur logika soft delete, seperti menampilkan data aktif, menampilkan data yang sudah dihapus, melakukan restore, dan menghapus permanen. 

// menampilkan data termasuk yang sudah dihapus
                $users = User::withTrashed()->get();

                // hanya data yang sudah dihapus
                $deleted = User::onlyTrashed()->get();

                // restore data
                User::withTrashed()->find($id)->restore();

                // hapus permanen
                User::withTrashed()->find($id)->forceDelete();
Manfaat Soft Delete:
  • Recovery Data → data yang terhapus bisa dikembalikan
  • Audit Trail → histori perubahan data tetap tersimpan
  • Historisitas → memudahkan analisis perubahan data
  • Keamanan → data tidak langsung hilang secara permanen
  • Menghindari error relasi jika data masih digunakan tabel lain
Menggunakan Constraint pada Database

Dalam pengisian data ke dalam tabel database, kita menginginkan data yang akurat dan konsisten. Untuk itu digunakan aturan yang disebut constraint.

Constraint adalah aturan pada kolom atau tabel yang memastikan data yang masuk memenuhi kondisi tertentu sehingga integritas data tetap terjaga. 

$table->string('email')->unique();
                $table->foreignId('user_id')->constrained()->onDelete('cascade');
Manfaat Constraint:
  • Mencegah data tidak valid masuk ke database
  • Menjaga hubungan antar tabel
  • Menghindari data orphan (data tanpa relasi)
  • Meningkatkan konsistensi dan integritas data

Beberapa jenis constraint yang umum digunakan:

  • NOT NULL → kolom tidak boleh kosong
  • PRIMARY KEY → identitas unik setiap baris
  • FOREIGN KEY → menghubungkan antar tabel
  • UNIQUE → memastikan tidak ada data duplikat
  • CHECK → memastikan nilai memenuhi kondisi tertentu
  • DEFAULT → memberikan nilai otomatis jika tidak diisi
Auto Increment vs UUID

Dalam database biasanya primary key menggunakan auto increment. Namun pada sistem modern sering juga digunakan UUID. 

$table->id(); // Auto Increment

                $table->uuid('public_id')->unique(); // UUID
Perbandingan:
  • Auto Increment → lebih ringan dan cepat untuk operasi database
  • UUID → lebih sulit ditebak dan cocok untuk API publik
  • UUID cocok untuk sistem distributed atau microservice

Praktik yang sering digunakan pada sistem besar adalah pola hybrid:

Schema::create('users', function (Blueprint $table) {
                    $table->id(); // internal primary key
                    $table->uuid('public_id')->unique(); // identifier publik
                    $table->string('name');
                });

Dengan pola ini, database tetap efisien menggunakan integer sebagai primary key, namun aplikasi menampilkan UUID sebagai identifier publik.

Jangan Tampilkan ID Database di UI

Sebaiknya jangan menampilkan ID database langsung di URL atau UI karena ID auto increment mudah ditebak. 

Contoh yang tidak disarankan:
                http://website.com/user/15

User bisa mencoba menebak data lain:

http://website.com/user/16
                http://website.com/user/17
Alternatif yang lebih aman:
  • Menggunakan UUID
  • Menggunakan slug
  • Menggunakan hash id
Perlindungan dari XSS (Cross Site Scripting)

XSS adalah serangan dimana attacker menyisipkan script berbahaya ke halaman web. 

{{ $nama }}

Blade Laravel secara otomatis melakukan escaping HTML. 

{!! $nama !!}
Catatan Penting:
  • {{ }} aman karena otomatis escape HTML
  • {!! !!} hanya digunakan jika benar-benar dipercaya
  • Gunakan validation dan sanitasi input
Mass Assignment Vulnerability

Mass assignment terjadi ketika aplikasi mengizinkan pengguna mengirimkan parameter tambahan yang tidak seharusnya, sehingga dapat mengubah field sensitif (misal: is_admin, role_id).

Contoh kerentanan: Endpoint registrasi hanya mengharapkan email dan password, tetapi penyerang menambahkan role=admin dalam request. Jika aplikasi langsung memetakan semua input ke model, maka penyerang bisa menjadi admin.

Pencegahan di Laravel:

  • Gunakan properti $fillable pada model untuk mendaftar field yang boleh diisi massal.
  • Alternatif: $guarded untuk melindungi field tertentu.
  • Gunakan Request::only() atau $request->validated() (setelah validasi) untuk membatasi input.
class User extends Model
{
    protected $fillable = ['name', 'email', 'password'];
}

// Di controller
User::create($request->only(['name', 'email', 'password']));
// atau lebih baik dengan form request validation
$validated = $request->validate([...]);
User::create($validated);
🛡️ Tips

Jangan pernah menggunakan Model::create($request->all()) tanpa proteksi fillable/guarded.

Validasi Data di Sisi Klien (HTML5)

Jangan percaya begitu saja pada input pengguna. Validasi di sisi klien memberikan umpan balik cepat, namun tetap harus divalidasi ulang di server. HTML5 menyediakan berbagai atribut untuk validasi dasar.

Atribut Penting:

  • required → field tidak boleh kosong.
  • type="email", type="number", type="tel" → memeriksa format.
  • min, max → batas angka.
  • minlength, maxlength → panjang teks.
  • pattern → regex kustom.
  • accept → jenis file (untuk upload).
<input type="text" name="username" required minlength="3" maxlength="20">
<input type="email" name="email" required>
<input type="number" name="usia" min="17" max="100">
<input type="file" name="foto" accept="image/*">
<input type="text" name="grade" pattern="[A-F][+-]?|D">

Untuk kustom pesan error, gunakan JavaScript:

input.addEventListener('invalid', function() {
    this.setCustomValidity('Isian tidak valid');
});
⚠️ Catatan

Validasi HTML5 hanya untuk kenyamanan pengguna. Tetap lakukan validasi server-side untuk keamanan.

CSRF — Ancaman & Pencegahan

CSRF adalah serangan yang memaksa pengguna terautentikasi mengeksekusi aksi yang tidak diinginkan (misal: ubah password, transfer dana) tanpa sepengetahuannya. Penyerang memanfaatkan sesi aktif korban.

Contoh skenario: Pengguna membuka situs jahat yang memuat gambar dengan src="http://bank.com/transfer?to=attacker&amount=1000". Karena pengguna sudah login di bank, browser otomatis mengirim cookie dan request tersebut dianggap sah.

Cara Mencegah di Laravel:

  • Laravel sudah menyertakan CSRF token otomatis untuk setiap form dengan @csrf.
  • Pastikan token divalidasi di server (Laravel menangani secara otomatis).
  • Gunakan metode POST/PUT/DELETE untuk aksi yang mengubah data, bukan GET.
<form method="POST" action="/transfer">
    @csrf
    <!-- field lainnya -->
</form>
🔒 Tips Tambahan
  • Set cookie dengan SameSite=Lax atau Strict.
  • Untuk API stateless, gunakan token (JWT) dan pastikan origin request diverifikasi.
SQL Index — Mempercepat Query

Index adalah struktur database yang mempercepat pencarian data pada kolom tertentu, seperti indeks di buku. Tanpa index, database melakukan full table scan — lambat untuk tabel besar.

Cara Kerja: Index membuat pointer ke baris data, sehingga query WHERE pada kolom yang di‑index bisa langsung menemukan data tanpa membaca seluruh tabel.

Jenis Index:

  • Clustered: mengubah urutan fisik data sesuai index. Hanya satu per tabel (biasanya primary key).
  • Non‑clustered: struktur terpisah berisi salinan kolom yang di‑index dan pointer ke data. Bisa banyak.

Contoh pembuatan index di Laravel migration:

Schema::table('users', function (Blueprint $table) {
    $table->index('email'); // non-clustered
    $table->unique('email'); // unique index
});

Contoh langsung SQL:

CREATE INDEX idx_users_email ON users(email);
📊 Kapan Perlu Index?
  • Kolom yang sering muncul di WHERE, JOIN, atau ORDER BY.
  • Hindari index pada kolom yang jarang digunakan atau nilai unik sedikit (misal gender).
  • Terlalu banyak index bisa memperlambat INSERT/UPDATE/DELETE.
Logging Efektif untuk Observability

Logging bukan sekadar console.log(). Di sistem modern (microservices, cloud), log harus terstruktur (JSON) dan terpusat agar mudah dicari dan dianalisis.

Level Log: DEBUG, INFO, WARN, ERROR, FATAL.

Structured Logging (JSON):

{
  "timestamp": "2025-03-17T04:20:00Z",
  "level": "error",
  "service": "order-service",
  "request_id": "uuid-123",
  "message": "Database connection lost",
  "user_id": 42
}

Centralized Logging: ELK Stack, Loki, Datadog — kumpulkan semua log di satu tempat.

Best Practices:

  • Sertakan request_id untuk melacak request lintas layanan.
  • Jangan log data sensitif (password, token).
  • Gunakan pustaka seperti Pino (Node.js), Monolog (PHP), Logrus (Go).
  • Async logging agar tidak blok performa.

Contoh dengan Laravel (menggunakan Log::):

use Illuminate\Support\Facades\Log;

Log::channel('stack')->info('User logged in', [
    'user_id' => $user->id,
    'ip' => request()->ip()
]);
🔍 Manfaat Logging Efektif
  • Debugging lebih cepat
  • Audit trail untuk keamanan
  • Pemantauan performa real-time
